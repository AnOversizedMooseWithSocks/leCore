# Typed decisions, the swarm contract, and the NOOA discipline — syntax reference

The Jev-shaped decision surface (sweeps 171–176) and the NOOA properties carried onto it. Every JSON block
below was GENERATED by calling the live engine (`tools/gen_typed_examples.py` prints each block under its `###`
title; section 8b's three blocks come from their own runs), so the shapes cannot drift from the code;
regenerate them after any change to these doors. Measurements behind each door are in `docs/research/` (start
at `RESEARCH_00_INDEX.md`; the benchmark tables in `BENCHMARK_sweep176.md`; the CLM backlog pass of sweep 182 --
sections 8d and 8e -- in `BENCHMARK_sweep182_contrastive.md`).

## 0a. The natural path -- what happens without asking for it

Since sweep 176 the discipline below is BUILT IN to the doors an agent already uses; nothing has to be
switched on:

- `mind.route(task)` is tiered: `act` (with `skill`, `tier`, `z`, `id`) when the task clears the answer
  floor, `choose` with `options` and a four-part `prompt` in the menu band, `abstain` only in the gibberish
  band. The previous node scored `act` at 0.75 for "purple monkey dishwasher"; `tiered=False` keeps it.
- `mind.tool_loop` / `mind.delegate` gate on the same tiers at the ACTING operating point (z_answer 0.1):
  an answer acts, a menu is returned as a `choose` decision without a model call (acting on a menu raised
  the no-tool false-action rate from 0.00 to 0.25, measured), the gibberish band refuses.
- `mind.find_capability`, `mind.suggest`, `mind.serve` and `mind.route` LEARN from use: once an outcome
  has been reported by id for a request like this one, the capability that was actually used comes first
  (`via="reflex"`); until then every result is identical to before.
- `mind.typed(state, [options])` is the one-line typed decision: the schema is built, linted (with the
  findings attached to the answer), scored by the measured regime table, and recorded.
- every typed answer, route and review carries an `id`; `mind.decision_outcome(id, truth)` is the one
  outcome path and everything -- the count table, the reflex, the calibration -- learns from it. Since sweep 182
  the ids survive a restart (section 8d) and every door reads its confidence the same way: `p_correct` (HIGH =
  confident, `None` until that door has calibrated) and `p_null` (LOW = significant); the bare `p` is a
  deprecated alias. The rank, serve, meaning and compose doors take outcomes by id too (section 8e).

## 0. Two ways to call every door

In process:

    import lecore
    mind = lecore.agent_boot()                       # or UnifiedMind(dim=256, seed=0) with no memory
    mind.systemone_decide(state, questions, scorer="nb")

Over HTTP (the service auto-introspects every public mind method; every call below is one `POST /invoke`):

    curl -X POST http://127.0.0.1:8080/invoke -H 'Content-Type: application/json' \
         -d '{"name": "systemone_decide", "args": {"state": "...", "questions": {...}, "scorer": "nb"}}'

The reply is `{"result": ...}`; a refused call carries `"error"`. Two sandbox rules learned the hard way: the
service loads the code it was started with (restart it after an edit, or a new verb "does not exist"), and a
script run from another directory imports whatever `lecore` is first on `sys.path` (`PYTHONPATH=.` when a
PyPI leos-core is also installed).

## 1. The schema (`questions`)

Three question types. `choice`: `options` (>= 2 unique strings) with `examples` per option (a non-empty list;
keys a subset of options). `noul`: yes/no with `examples` keyed `yes` / `no`. `score`: numeric `min` < `max`
with `anchors` as **(text, value) pairs** — a value-keyed dict is refused by `validate_questions`.

## 2. Deciding: `systemone_decide` / `systemone_map` / `systemone_stream`

`systemone_decide(state, questions, labeled=None, margin=None, encoder="perceive", min_support=None,
scorer="prototype"|"nb", nb_bigrams=False, conformal_alpha=None, reflex=False, escalate=None, p_floor=0.5,
verify=False)`. Use `scorer="nb"` (the transformed count table) from ~20 examples per option; `encoder="ngram"`
for text. `labeled=[[state, {question: truth}], ...]` calibrates `p_correct` (isotonic; needs ~150 rows to be honest)
and, with `conformal_alpha`, the answer `set` — the options guaranteed to hold the truth with probability
1 − alpha (Banking77: nominal 0.95 → 0.960 measured). Every answer carries an `id`.

Answer fields: `ranked` (option, score), `value` (None when abstained — `why` says why), `margin_gap`,
`confident`, `p_correct` (None until calibrated; HIGH = confident), `p_null` (None here: a typed answer has no
null), `set` / `set_alpha` (conformal), `via` (`typed` | `reflex` | `escalated`), `id`. The `p` key in the JSON
is the deprecated alias of `p_correct` (kept one release; reading it in process warns -- section 8d).
`scorer="contrastive"` (sweep 182) moves the prototypes by the shared InfoNCE rule on every outcome and adds
`p_top` (section 8e). `systemone_map(states, ...)` returns one such dict per state; `systemone_stream(rows,
questions, lr=1.0)` runs prequentially and returns `prequential_accuracy`, `drift`, `calibrated`.

More doors on the same fitted model (kept per schema, so outcomes accumulate): `systemone_batch_fdr(states,
questions, question, alpha, n_null=200)` → `{accepted, p, q, n, p_null}` (BH over shuffle-null p-values, which
`p_null` carries -- `p` is their deprecated alias; FDR 0.03 at
nominal 0.05 measured; use ≥ 200 nulls); `systemone_absorb(states, questions, question)` → guarded EM over
unlabeled states (refused above 10 options; kept only if held-out accuracy did not fall; plain NB + EM
0.697 → 0.752 on AG News k=32).

## 3. Outcomes by id — the only outcome path

`decision_outcome(id, truth)` reports what actually happened. For a typed decision it forwards to the fitted
model's `observe` (the count table learns; prequential 0.699 → 0.764 with zero model calls), writes the
experience to the lever-7 reflex trace, and feeds that door's OWN calibrator (section 8d). Report `"failed"` (or
`None`) when NO truth is known — that, and only that, marks the reflex's failure field; a correction is written as
the truth (and the wrong answer unlearned: section 8d). Ids survive a restart (section 8d).

### decision_outcome(id, truth) -> report
```json

  "forwarded": {
    "was_correct": true,
    "updated": true

  "was_correct": true,
  "door": null,
  "reflex": {
    "learned": true,
    "was_correct": true,
    "write": {
      "accepted": true,
      "surprise": 1.0,
      "load": 0.00048828125,
      "tiles": 1

```


`decision_records(k)` lists the ledger with `stats`; `decision_ledger()` is the store (`similar(id)` finds a
like decision by cosine of the HRR-encoded records); `decision_ledger_to_memory()` teaches every reported
record into the partition so `ask("decision: <question> :: <state>")` recalls it at T0.

## 5. The reflex arc learning from use

Opt in with `reflex=True` on `route_tiered`, `decision_tree`, `systemone_decide`. The reflex answers only
behind the SEEN gate — a reported decision key within cosine 0.8 of the query (keys: the routing fingerprint
for routes and trees, the state's n-grams for typed decisions) — because trace confidence alone cannot tell a
repeat from a wrong fire. Measured on the router with both paraphrases ablated: repeats answered from
experience 99.3% at 0.982; new paraphrases 20.9% at 0.81. For typed decisions the count table stays the
learner (the reflex measured worse there), so it is off by default.

### route_tiered(reflex=True) after the outcome: the repeat answered from experience
```json
{
  "tier": "answer",
  "answer": "Smooth a bumpy mesh surface (Taubin no-shrink)",
  "via": "reflex",
  "confidence": 0.5246689212697481,
  "id": "86d4fd25dc4d017c",
  "reason": "answered from experience (reflex confidence 0.52)",
  "p_correct": null,
  "p_null": null
}
```


`reflex_learn(id)` is what the outcome path calls; `reflex_decide(state, key)` is the raw read; `reflex_retile
(advisory_load=0.03)` rebuilds the trace at the measured capacity cliff (a trace loaded by `boot` under the old
tiling reads back under the floor; the first reflex read after boot re-tiles itself).

## 6. Verifying a served answer: `verify_decision`

`verify_decision(state, answer, key="ngram"|"fingerprint")` → `{valid, score, checks, why}`. Five checks with
evidence: `forward` (the trace read with the state cleans up to the answer), `backward` (the trace read with the
answer atom points back at the state — the bidirectional lookup), `profile` (displacement against reported-
correct pairs), `seen`, `drift_z` (support against the recent stream; < −2σ vetoes). Both lookups are RELATIVE
to the other labels (`forward_margin`, `backward_margin`) — an absolute floor let a wrong label through on a
loaded trace. Measured: a seen state served the truth verifies 0.97–0.99 valid, a wrong label 0.00 (forward and
backward AUROC 1.000). It is a verdict, not a confidence: the calibrated margin ranks. `valid` is `None` when
there is no experience to check against — never a guess. `route_tiered(..., verify=True)` attaches it.

### verify_decision(state, answer) -> verdict

## 7. The swarm step contract (NOOA's validated termination)

`swarm_step(state, tool, args, done_when, evidence, worker, topic="swarm", verify=None, expect=None)` is
REFUSED without `done_when` and `evidence`. With `verify={"verb": <mind verb>, "args": {...}}` and `expect`
(a value, or a callable over the result), the harness RUNS the verification before the step is accepted; a
failed verification never reaches the bus. Accepted steps are DecisionRecords (via `swarm`) published on the
mind's MessageBus. `swarm_evaluate(audits=(...))` runs `reachability_audit`, `catalog_gaps`, `skill_lint` as
subprocesses and returns `all_ok` — the evaluator role and the hard exit. Since sweep 182 every verified step
is also a labelled example for `verify_precheck` -- a passed verify a SUCCESS, a failed one a FAILURE (before, a
refused step taught nothing) -- and the record's `meta.precheck` carries the score the step had before its verify
ran (section 8e).

## 8. The NOOA properties, and where each lives

| NOOA (arXiv 2607.20709) | on these doors |
|---|---|
| validated termination — typed result with evidence and a verification command checked before return | `swarm_step(verify=, expect=)`; `decide_or_escalate` validates the model end's reply to the schema, one retry |
| docstrings as prompts, annotations as contracts | `SystemOne.escalation_prompt` renders the four-part prompt (goal / return format / constraints / verification) from the schema; the payload carries `prompt` and `spec` |
| pass-by-reference with bounded previews | `DecisionRecord.to_dict` ships a state over 400 chars as `{ref, len, preview}` |
| long-term memory (ACT-R activation, decay, reflection) | `decision_ledger_to_memory()` + `memory_curate` |
| model-queryable event history | `decision_records()`, the bus history, `Ledger.similar()` |
| code as action; sandboxed execution | absent by decision (no exec REPL; the engine never runs model-written code) |

The model end: `systemone_decide(..., escalate=callable)` routes an abstention through `decide_or_escalate`;
the callable receives `{question, spec, state, evidence, why, prompt}` and must return one of the options (or
null). Its answer is a record `via="model_end"`; once its outcome is reported, the reflex answers the next
similar task itself — leOS's self-extending instruction (measured: one model call, then none).

## 8b. The code workflow: plan, edit under validated termination, review with evidence

Three doors compose the engine's existing code faculties (`code_search`, `code_similar` -- Rule 0 asked of
the source -- `function_purity`, `affected_tests`, `file_python_check` / `file_import_check` /
`file_selftest`, `file_undo`, the audits) into the path an LLM should follow when it writes code through
leCore. Each is a record; each has a measurement.

**Plan.** `plan_change(request)` gathers the evidence -- the catalog's tier and z, the nearest source by
`code_search`, the family -- and decides reuse / extend / build: the measured tier decides where it is
decisive, modification intent ("add a parameter to X") turns an answer-tier hit into *extend*, and the typed
decision breaks the menu tie and learns from `decision_outcome(id, "reuse"|"extend"|"build")`. The steps are
the build loop with a `done_when` each. Measured on 12 historical requests: 11 of 12 against today's truth
(majority 0.33); the three original misses were two catalog gaps the plan exposed (fixed as aliases) and the
intent rule.

## 8c. Finding by meaning, and the typed model end (sweep 181)

The reflex answers **near-exact repeats only** (by design: a looser gate served one-word-different questions
each other's answers). Everything else used to be refused, so a person who rephrased a taught question got
nothing back: on real human wording, 0.1% of CLINC150's held-out phrasings and 0.0% of Banking77's were served.
The meaning rung (`holographic_meaning.MeaningIndex`, wired by UnifiedMind part 28) sits right after the reflex:

- **A row, many wordings.** Each taught answer is a row; every wording confirmed to mean it joins the row (never
  a duplicate row with a copied answer). Matching is content stems + bigrams + character 4-grams, IDF over rows,
  best wording blended with the row centroid, plus **learned word associations** from every confirmed link.
- **Serve / clarify / escalate.** Serving needs confidence: a strict near-exact gate at cold start, then a
  calibrated P(the model would agree) from the verdicts themselves (isotonic, the SystemOne PAV fit), held to
  the teacher's own agreement ceiling. A rare word that belongs to another row blocks the serve (near-miss).
- **The typed model end.** An unsure question goes to the attached model with the nearest rows as evidence and
  a JSON return contract, validated and retried once:

```text
{"verdict": "same", "row": "<row id>"[, "args": {...}, "from_question": {...}]}
{"verdict": "new", "answer": "...", "method": {"verb": "<tool>", "args": {...}, "from_question": {...}, "live": true}}
{"verdict": "unclear", "clarify": "<one question for the person>"}
```

  `same` links the wording (learned on the spot); `new` teaches the answer through the learning guard -- or,
  with a `method`, keeps **how the answer was found** (verb + slots mapping the question's words to tool values)
  and never the live value itself; `unclear` keeps the clarifying question. A reply that ignores the contract is
  used as a plain answer, as before. Every verdict is also a calibration label.
- **Methods run fresh.** A matched method binds its slots from the question and runs the registered tool
  (`meaning_tool_register(verb, fn)`), or returns the call as a plan when the tool lives in the caller's process.
  A question that is only a value ("SOL", "eth?") is clarified, never acted on; a question that gives more than
  the learned call uses ("20 yen" when the method has no amount) is escalated so the method can grow the slot.
- **Out-of-process models.** `serve()`'s escalation carries `meaning: {prompt, candidates}`; answer the prompt
  anywhere and report the reply with `meaning_resolve(query, reply, by=...)`. Every meaning serve returns an
  `id`; `decision_outcome(id, <right row id>)` corrects a wrong serve and teaches the wording.

```python
m.teach("how do i check my account balance", "Open the app and tap Accounts.")
row = list(m.meaning.rows)[0]
m.meaning_resolve("how much money do i have left", {"verdict": "same", "row": row})
m.ask("How much money do I have left?")        # -> via "meaning", the taught answer, an id to correct it
m.meaning_report()                              # rows by kind, wordings, associations, calibration
```

Numbers (CLINC150, Banking77, a hand-written crypto set; scripted stand-in model, oracle and noisy):
`docs/research/BENCHMARK_sweep181_meaning.md`.

## 8d. One loop: p_correct, p_null, persisted decisions, trace correction (CLM backlog Phase A, 2026-09-26)

The CLM panel (docs/research/evidence/clm_panel_20260926/) measured the reflex arc before arguing about it and
found its SUBSTRATE broken in four places: the ledger forgot every decision at a restart, `p` meant opposite things
at different doors, two doors shared one calibration curve, and a correction written into the reflex trace could
not unlearn the wrong answer. This section is what changed. Pinned by `tests/test_arc_substrate.py`.

### One meaning of p (E0.6)

Every door's record now carries two named numbers. **`p_correct`** is a calibrated P(this answer is correct):
HIGH = confident, `None` until that door's own calibrator has labelled outcomes of both kinds (an uncalibrated door
says so instead of inventing a number). **`p_null`** is a significance p-value against a null where the door has
one: LOW = significant, else `None`.

| door | score it calibrates | p_correct from | p_null |
|---|---|---|---|
| `route_tiered` (catalog path) | z | `door_calibrator("route")` -- P(the top option is the capability you used \| z); a menu is scored on its top option | the catalog's empirical in-vocabulary null p-value |
| `route_tiered(reflex=True)`, `reflex_decide`, `serve` (reflex path) | reflex confidence | `door_calibrator("bridge")` | `None` |
| `typed` / `systemone_decide` | margin_gap | the fitted SystemOne's own isotonic calibrator (per question) | `None`; `systemone_batch_fdr` returns its shuffle-null p's as `p_null` |
| meaning (`ask` served by meaning) | MeaningIndex confidence | the MeaningIndex's isotonic calibrator | `None` |
| `serve` tool reflex | word overlap (`score`), or the experience confidence for a judged pick | `door_calibrator("tool:overlap")` / `("tool:experience")` -- two scales, two calibrators | `None` |

Every door calibrator is fed by `decision_outcome` on that door's records only (`correct = answer == outcome`); a
failed tool verdict is fed straight to its calibrator (a `"failed"` outcome would paint the failure field). The
`DecisionRecord` gained optional `p_correct` / `p_null` fields; **record ids did not change** (neither is hashed).

**The bare `p` stays one release, deprecated.** It keeps its OLD per-door value (the catalog's null p-value; the
reflex's 1 - error), so nothing that reads it changes behaviour -- but reading it (`r["p"]`, `r.get("p")`) emits a
`DeprecationWarning` once per process per door. Results are `DecisionDict`s: a dict subclass, so `json.dumps`, the
HTTP service's wire conversion and `dict(r)` behave exactly as before and never warn. Also fixed: the typed reflex
path computed `p` as `err is not None and (1 - err) or None`, which turned a calibrated 0.0 into `None`.

```python
r = m.route_tiered("smooth a bumpy mesh")
r["p_null"]      # 0.0154 -- the top score beats 64 in-vocabulary word-salad queries (LOW = significant)
r["p_correct"]   # None until route outcomes are reported; then P(correct | z) (HIGH = confident)
m.door_calibration_report()   # {door: {labels, correct, calibrated}} for every door calibrator this mind holds
```

### Calibration streams per door (E0.7)

`calibrate_reflex` used to fit ONE isotonic curve from a list fed by two doors -- the ladder's T0 reflex
(`answer_feedback`, on the ladder key's confidence) and the reflex bridge (`reflex_learn`, on bridge confidences) --
and that one curve drove both the ladder's `calib_veto` and the bridge's `p`, so every bridge outcome moved the
ladder's veto. Now `door_calibrator("ladder")` and `door_calibrator("bridge")` are separate instances of one class
(`holographic_protostore.DoorCalibrator`); `reflex_error_prob(conf, door="ladder"|"bridge")` reads either. Pinned:
twelve ladder labels, then the bridge reports right and wrong answers -- the ladder's pairs, its p_correct at eleven
confidences and its veto function are unchanged. **The ladder's veto is wired on load**: before, `_error_prob` was
set only inside `calibrate_reflex`, so after a restart the veto stayed OFF until 8 new reports; now a reloaded mind
vetoes at once (pinned against an un-calibrated control mind that serves the same rewording at T0). The partition's
calibration section is v2 (`streams`: one per door); a v1 partition's untagged `pairs` list is **migrated into
BOTH the ladder and the bridge stream** -- nobody recorded which door wrote which pair, so each door starts from the
shared history it used to be calibrated on and its own labels take over through the calibrator's window (512).
v2 still writes the untagged `pairs` (ladder + bridge) so an older build opening a new partition keeps a curve.

### Decisions survive a restart (E0.5)

The ledger lived in process memory: `decision_outcome(<an id issued before a restart>)` raised KeyError, and every
lesson a typed decision's SystemOne had learned was lost. Now:

- **`lecore.learning.decisions`** (a container section, written by `learning_save`, restored by `learning_load`,
  carried by `learning_rollover` -- older generations contribute the records the newest lacks, sorted first):
  records as TEXT, so ids re-derive and a changed id function migrates by replay; the stored id is checked, and a
  mismatch keeps the old id as an alias so an outcome reported against it still lands. The newest 4,096 are kept.
  A record whose state, question, answer, outcome or meta carries a secret (the learning guard's pattern layer) is
  **never written** -- it is counted (`dropped_sensitive`).
- **SystemOne's learned tables** travel in the same section: prototype matrices and accumulators, NB counts, the
  isotonic fit, conformal quantiles, the outcome and support streams (`SystemOne.state()` / `load_state()`), for
  every cached SystemOne that has LEARNED (one that only decided is re-derived from its schema by fit). A decision
  after a cold reload is bit-identical to the one before (pinned) and differs from a fresh fit.
- **Hooks are re-derived, not closures.** A typed record names its door in `meta["hook"]` (the SystemOne cache key
  + question); a meaning record names the meaning door. `Ledger(resolve_hook=...)` rebuilds the callable at report
  time, so a reloaded record trains the right door. The typed hook refuses to learn a state carrying a secret (the
  NB table would otherwise count a pasted password's tokens -- and that table is persisted now).
- **A hook that raises no longer aborts the report.** `SystemOne.observe` raises SchemaError for an outcome that is
  not an option; that used to escape `Ledger.report`, so `decision_outcome` never reached `reflex_learn`. The error
  is carried as `hook_error`; the outcome, the seen gate and the calibration still happen.
- **A yes/no decision learns the string "no" as no.** `observe` computed `want = "yes" if truth else "no"`, so the
  STRING `"no"` (truthy) was learned as YES; any other non-yes/no string is now refused, not learned.
- Cost, measured (2 cores, load average ~7 from parallel workers): 4,200 decisions -> the newest 4,096 kept; the
  whole partition file 246,019 bytes (the section's meta is 3.08 MB of JSON before the container's zip); save
  3.2 s, cold load 0.46 s. The ledger's HRR encoding is now LAZY (only `similar()` needs it): it cost 3.5 ms per
  record, i.e. ~14 s to reload 4,096 records at boot.

### The reflex trace can unlearn (E1.5)

A correction -- `decision_outcome` with a truth different from the answer the door served -- used to do
`write(k, truth)` and nothing else. `write()` corrects ALONG the truth atom and clamps the stored strength at
s >= 0 (the right rule for learning a lesson), so it can never UNLEARN one: the wrong atom kept its full strength.
Both designs the panel proposed were built (`holographic_lever7.correct_lms_apa` / `correct_by_provenance`) and
measured; the owner's rule was "build both, let the measurement choose".

- **(a) `lms_apa` -- codebook LMS + affine projection (the default).** `err = sum_l (onehot(truth) - s)_l L_l` over
  the bridge's label atoms read at |s| >= 0.2 (plus the target), bound to `u` = the minimum-norm key with
  `<u,k> = 1` and `<u,k'_j> = 0` for up to 8 nearest REPORTED keys of the same kind whose outcome differs and whose
  cosine to k is in [0.4, 0.95) (below 0.4 an unprotected neighbour keeps its answer 0.973 anyway; at and above
  0.95 it IS this question, superseded). One write fixes the leak and the truth, whatever wrote them.
- **(b) `provenance`.** `write(k, truth)`, then: the wrong atom was written AT this key (audit key cosine >= 0.95)
  -> a signed along-atom write `-s_a L[a]`; it leaked from a neighbour -> an outcome-role negative `bind(NEG, L[a])`
  that a read with `neg_role` consults (a label whose negative read beats its positive is suppressed).
- **Raw entries replay VERBATIM.** A signed delta pushed back through `write()` would be re-estimated, clamped and
  dropped -- every replay would silently undo every correction. `DisplacementTrace.write_raw(k, delta, mode)`
  journals a flagged audit entry (modes: bind along k / add a pre-bound trace delta routed by k / register an
  atom), and `replay`, `from_state`, `TiledDisplacementTrace._split`, `reflex_retile` and the partition's instanced
  audit (a per-row `aud_raw_<tile>` flag array; old files have none and load as before) all apply it verbatim;
  audit regen refuses while raw entries exist. Also fixed here: `experience_from_state` rebuilt the tiled trace
  without `advisory_load=0.03`, so a reloaded mind's future splits reverted to the old 0.10 (past the cliff).

MEASURED (`PYTHONHASHSEED=0 python tools/bench_trace_correction.py --data <dir>` ->
`docs/research/evidence/bench_trace_correction.json`): real CLINC150 questions as hashed-n-gram keys (dim 2048),
labels `derived_atom(0, "answer:" + intent)`, 40 background rows per trace, the mind's TiledDisplacementTrace,
150 trials per cell, data sha256 36923c37...; the reflex's argmax read (the gated read the reflex SERVES agrees in
every cell):

| arm | same key, 1 correction | 3 corrections | flip-flop (A -> B -> A) | neighbour keeps its answer, c = 0.5 / 0.8 / 0.9 | background intact | replay / reload agreement |
|---|---|---|---|---|---|---|
| `current` (BASELINE, before E1.5) | 0.453 | 0.660 | 0.453 | 1.000 / 0.900 / 0.813 | 1.000 | 1.000 |
| **`lms_apa` (DEFAULT)** | **1.000** | **1.000** | **1.000** | **1.000 / 1.000 / 0.993** | 0.995 (worst cell, c = 0.9) | **1.000** (bit-identical reload) |
| `provenance` | 0.993 | 1.000 | 0.993 | 1.000 / **0.780** / 0.533 | 1.000 | 1.000 |

Acceptance: same key >= 0.95 (baseline 0.453), neighbour kept >= 0.85 at c = 0.8 (baseline 0.900), replay 1.000.
**`lms_apa` meets all three and is the default** (`reflex_correction_mode()`); `provenance` stays selectable with
`reflex_correction_mode("provenance")` and FAILS the neighbour bar (0.780 < 0.85) -- the panel's own w2 number
reproduced to the digit. The baseline reproduces the panel's 45.3% / 66% / 90% exactly. What (b) did gain here:
the panel measured its audit replay at 77-87% agreement; replayed verbatim it is 100%.

Kept negatives, measured and on record:
- **The affine projection is what protects the neighbour.** The same LMS step along k itself (`lms_noproj`: no
  protected keys) fixes the key just as well (1.000) but the neighbour keeps its answer only 0.847 at c = 0.5,
  0.38 at 0.6, 0.02 at 0.7 and 0.000 at 0.8 -- w2's signed-write finding, generalised to the whole codebook.
- **The first protection line sat AT 0.5**, and a neighbour at exactly 0.5 fell on the wrong side of float
  rounding: `lms_apa` kept 0.847 there, i.e. unprotected (first full run). The line is 0.4; 0.5 now keeps 1.000.
- **Design (b) without retracting an earlier rejection** (its first cut): a noisy verdict at a key records "y is
  wrong here"; when the truth y is reported back, that stale NEG(y) outvotes the fresh write -- flip-flop read
  back 0.373 (the mind-level test saw the reflex go silent). (b) now cancels a rejection of the truth at the key
  before writing it (0.993).
- The cost of (a): with a neighbour protected at c = 0.9 (|u| = 2.3) the write adds enough crosstalk that 0.5% of
  background rows (40 per trace) flip; 0.1% at 0.7-0.8, none below.

### Meaning serves become verifiable (E5.3)

`reflex_learn` returned early for `via == "meaning"`, so `verify_decision` could never vouch for a meaning serve.
A reported meaning decision now joins the seen gate under its OWN key kind (`"meaning"`: the question's hashed
n-grams, invisible to the typed and tool doors' seen gates) and a meaning displacement profile; the experience
TRACE is still not written (the lesson lives in the MeaningIndex, whose vetoes a second copy would sit outside).
`verify_decision(query, row_id, key="meaning")` vouches only through the seen gate -- a confirmed wording at cosine
>= 0.8 whose outcome was THIS row; the trace's forward/backward reads are not evidence here (they would be pure
crosstalk), and the drift check is the MeaningIndex's own calibration. Pinned: not vouched before the outcome,
vouched after `decision_outcome(id, row)`, a different row not vouched, and the row id never becomes a trace label.

### One tool learner (E4.3, E4.4)

`serve`'s tool reflex now chooses among learned tools through `ProtoStore("tool")` -- one prototype per
`service.endpoint`, seeded by each taught pattern, pulled by a verified call, and for a correction the truth is
pulled and the wrong pick pushed as a labelled negative; a failed verify with no known right tool is a negative
only; an unjudged call teaches nothing. Until the first judged verdict the door is cold and the old two-word
overlap pick runs bit for bit. `tool_key(text)` is the door's key (the question's hashed character n-grams -- the
reflex bridge's key, so the two see one space); `tool_note` / `tool_predict` / `present_tools` read and write the
door. UsageTrace is a read-compat shim: an old partition's per-tool success / failure COUNTS migrate into the door's
audit tallies; its trace vector does not (its keys were `semantic_key` vectors, a different space). NOT
RE-MEASURED, kept loud: the backlog's acceptance bench (`tools/bench_tool_learning.py`, "not lower, no new wrong
calls") was not re-run in this pass; the door is pinned by 16 tests (a corrected call changes the next pick for a
paraphrase; a failed verify moves it; unjudged calls move nothing; the door survives a restart).

### Learned prototypes travel through the commons (owner's Q3: yes, behind the guard)

`contribute` / `commons_pool` now carry learned `ProtoStore`s. `protostore_share(door, on=None)` reports or sets a
door's opt-in; the router and the tool door are shareable by default (their questions are capability and tool
wordings), any other door opts in. The guard still decides: a store travels only if EVERY question it learned
from passed the learning guard and none was session-salted -- a prototype is a sum and cannot forget one term, so a
single refused question bars the store for good. Merging weights rows by their verdict counts; two prototypes for
one label that point apart (cosine < 0.3) are FLAGGED as a conflict, never averaged. Three `contribute` gaps were
fixed on the way: a vetoed row was still exported, a `model-cached` (provisional) row could travel, and a row the
guard refused inside a bundle was counted as kept.

### `mind.rank(state, candidates)` -- free-form ranking, our way (E3.3)

Candidates are strings or `{"text", "id", "examples"}` (a candidate with examples is the bundle of its text and its
examples). The ORDER is the absolute cosine in the hashed character 3..5-gram space (dim 2048, the typed doors'
space); under the absolute floor 0.15 the door refuses (`value` None, the ranking still returned). `p_null` is the
top score's p-value against in-vocabulary word salad of the state's length (64 draws). `decision_outcome(id,
label)` feeds `door_calibrator("rank")`, the rank door's prototypes (learn=True scores learned rows) and a
conformal-style set (after 8 truths).

### The verifier pre-check (E5.2)

`swarm_step` now learns every verified step per tool into a two-option `ProtoStore("verify:<tool>")`: a passed
verify is a SUCCESS example of its state, a failed one a FAILURE example (before, a refused step taught nothing).
`verify_precheck(state, actions)` scores each action `cos(state, success) - cos(state, failure)` and moves an action
only on STRONG evidence (|score| >= 0.5), otherwise keeping the given order; it never skips a verify.

### Ledger hooks combine per id

A record id hashes (state, question, options, answer, via), so two doors can file one decision under one id -- an
