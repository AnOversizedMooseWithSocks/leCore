01 / THE CONTRACT

Small on purpose.

liblecore carries the reusable math. Your application keeps the meaning, rules, storage, and final say.

01

Semantics before speed

Direct kernels follow the Python reference. Faster backends ship only when values stay within bounds and observable decisions agree.

02

Exact decisions

Cleanup scans in a declared order. Exact ties select the lowest index. Unsupported acceleration fails loudly.

03

The host owns policy

The library does not generate atoms, choose actions, own a vocabulary, or mutate application state.

02 / MEASURED, NOT MARKETED

Fast where the evidence says so.

On the recorded Apple arm64 run, the portable radix-2 backend completed a 1,024-dimensional f32 bind in 13.43 μs. The ordered direct backend took 62.52 μs.

This is one machine and one operation—not a universal speed claim. AUTO still chooses the direct backend until adopter workloads earn a crossover rule.

cd leCore
cmake -S native/liblecore -B build/liblecore \
  -DLECORE_BUILD_TESTS=ON
cmake --build build/liblecore --parallel
ctest --test-dir build/liblecore --output-on-failure
